# Drawary 59화면 재구성 작업 기준

## 목적
기존 Drawary UI는 최종 확정된 59개 화면 디자인으로 대체한다. 확정된 화면은 임의로 변경하지 않는다.

## 적용 범위
- 교체 대상: `category-data-app/` (React/Vite 앱), `drawary-app/` (Android WebView 래퍼의 Drawary 관련 코드)
- 보존 대상: `PDkou/MySaveCode` 내 다른 앱·게임·독립 프로젝트, 기존 `claude/category-data-management-app-jo6f6i` 브랜치
- 개발 브랜치: `drawary/59-design-rebuild-20261014`
- 기존 코드는 새 구현·기능 검수가 끝날 때까지 삭제하지 않는다.

## UI 진척
- 디자인 검토 및 사용자 확정: 59/59
- 실제 React 앱 통합 및 빌드: 미완료
- 화면별 개별 HTML 데모는 완성품으로 간주하지 않는다.
- 47번 '백업 진행'은 에셋 적용 디자인 확정 상태이며 실제 구현 결과의 최종 검수는 별도 확인한다.

## 디자인 원칙
1. 최종 확정 레이아웃·색상·이미지 에셋을 재사용한다. 새 디자인을 임의 생성하지 않는다.
2. 각 화면을 React 컴포넌트로 통합하고 실제 네비게이션을 연결한다.
3. 작은 화면/가로화면/폴더블에서 여백·안전 영역·스크롤을 검수한다.
4. 전체 문장부호·공백 표기와 불필요한 흰색 외곽 패널은 화면 전체 완성 후 일괄 검수한다.
5. 미리보기는 실제 앱 코드에서 렌더링해 제공한다. 시안 이미지와 코드 렌더를 혼동하지 않는다.

## 데이터 및 기능 안전
- 기존 사용자 데이터를 초기화하거나 폐기하지 않는다. 로컬 데이터 형식과 마이그레이션을 먼저 확인한다.
- 기존 백업 JSON의 import/export, 병합/덮어쓰기 동작을 확인한 뒤 새 UI에 연결한다.
- Google Drive 연동 여부는 별도 구현·검증이 필요하다. 디자인만으로 동작한다고 주장하지 않는다.
- Android Storage Access Framework, 사진 관련 권한·재연결, 알림·반복, PIN/앱 잠금 등의 네이티브 흐름을 확인한다.
- 피드백 전송은 실제 연결되기 전까지 전송 성공이라고 표시하지 않는다.
