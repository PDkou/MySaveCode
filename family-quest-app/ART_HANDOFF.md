# 아트 에셋 인수인계 문서 (GPT/이미지 생성 도구용)

이 문서는 GAMIFICATION_DESIGN.md 10번("아트 에셋 방침")에서 예고한 대로, 캐릭터 꾸미기 시스템의
placeholder를 실제 아트로 교체하는 작업을 GPT(또는 다른 이미지 생성 도구)에게 넘기기 위해 작성했습니다.
**코드는 이미 다 짜여 있고 동작합니다** — 여기 필요한 건 이미지 에셋 제작 + 아래 통합 지점 한 곳을
바꾸는 것뿐입니다.

## 1. 앱이 뭔지 (3줄 요약)

"Family Quest"는 가족(또는 회사팀/개인)이 집안일·할 일을 "퀘스트"로 서로 의뢰하고 완료하는
React+Supabase PWA입니다. 완료하면 포인트/경험치가 쌓이고, 그 포인트로 상점에서 내 캐릭터를
꾸밀 수 있습니다 (RPG 느낌의 슬롯 이름을 쓰지만 전투/폭력 요소는 없는, 가족 전연령 톤의 앱입니다).

## 2. 지금 상태: placeholder 시스템

실제 이미지 파일이 하나도 없습니다. 대신 `src/components/CharacterSprite.tsx`가 **CSS 도형 +
이모지만으로** 캐릭터를 코드로 조립해서 그립니다:

- `body`/`background`/`top`/`pants`/`shoes` 슬롯 → **CSS 색상 hex 코드** (예: `#F4C99B`)를
  받아서 사각형/원 도형에 배경색으로 칠함.
- `head`/`weapon`/`shield`/`accessory1`/`accessory2` 슬롯 → **이모지 한 글자** (예: `👑`, `⚔️`)를
  받아서 그 위치에 그대로 텍스트로 표시.
- `title` 슬롯은 시각적 요소가 아니라 캐릭터 옆에 텍스트 칭호로만 표시됩니다 (예: "방치의 신") —
  **이 슬롯은 아트가 필요 없습니다.**

즉 데이터베이스(`shop_items.sprite_key` 컬럼)에 들어있는 값이 hex 코드거나 이모지거나 둘 중
하나이고, `CharacterSprite.tsx`가 그 값의 "의미"(색상인지 이모지인지)를 슬롯 종류로 미리 알고
다르게 처리합니다.

## 3. 통합 지점 (실제 아트로 바꿀 때 건드릴 곳)

**여기가 이 문서에서 가장 중요한 부분입니다.** 실제 아트가 생기면 딱 두 곳만 바꾸면 됩니다:

1. **`supabase/schema.sql`의 `shop_items` 시드 데이터** (아래 4번 표에 나열된 값들) — `sprite_key`
   컬럼 값을 hex/이모지 대신 실제 이미지 식별자(파일명 또는 URL, 예: `body_default.png`,
   `head_crown.png`)로 바꿉니다. 이미 배포된 DB가 있다면 `update public.shop_items set
   sprite_key = '...' where key = '...'` 형태로 개별 업데이트하는 마이그레이션이 필요합니다
   (스키마 구조 자체는 안 바뀜 — `sprite_key text` 컬럼은 이미 어떤 문자열이든 담을 수 있음).
2. **`src/components/CharacterSprite.tsx`** — 지금은 `equipped.body`를 `backgroundColor`로 직접
   쓰고 `equipped.head`를 `<span>{emoji}</span>`로 그대로 렌더링하는데, 실제 이미지로 바꾸려면
   각 슬롯을 `<img src={...} />` 또는 스프라이트시트 CSS로 바꿔야 합니다. 슬롯별 배치(포지션/크기
   비율)는 이미 잡혀 있으니 그 좌표는 그대로 재사용하면 됩니다 — 아래 5번 참고.

**바꾸지 않아도 되는 것**: DB 스키마 구조(`shop_items` 테이블 컬럼), 구매/장착 RPC
(`purchase_item`/`equip_item`/`unequip_item`), 상점 UI 로직(`CharacterShopModal.tsx`,
`TycoonModal.tsx`) — 이것들은 `sprite_key`가 뭘 담고 있든 신경 안 씁니다.

### 타이쿤(방치형) 화폐 전용 한정 아이템 (별도 취급, 위 표와 슬롯은 겹침)

포인트 상점이 아니라 "타이쿤 상점"(방치형 재화로만 구매)에서 파는 한정판 3종 — 등장 빈도가 낮은
보너스 성격이라 시각적으로 더 화려하게/특별하게 구분되면 좋습니다:

| 슬롯 | 아이템명 | 현재 placeholder |
|---|---|---|
| head | 별빛 왕관 | `✨` |
| background | 골드 러시 | `#F4D35E` |
| weapon | 황금 낫 | `🌾` |

칭호(title 슬롯)는 총 76개 텍스트 칭호가 있지만 (예: "방치의 신", "신입" 등) 위에서 말했듯
시각 요소가 없어서 이 목록엔 포함하지 않았습니다. 다만 칭호는 한국어(`shop_items.name`)/
일본어(`shop_items.name_ja`) 두 언어 이름을 각각 갖고 있어 아트와는 무관하게 이미 다국어 지원이
되어 있습니다 — 코스메틱 아이템(위 37종)은 아직 일본어 이름이 없어서 실제 아트 작업 시 이름을
붙일 계획이라면 이 부분도 함께 채워야 할 수 있습니다.

## 5. 슬롯 배치/비율 (CharacterSprite.tsx 기준, 캐릭터 전체 크기를 1이라 할 때)

캐릭터 컨테이너는 정사각형이고 `background` 색이 그 정사각형 전체를 채웁니다. 그 안에이 순서로
쌓입니다 (뒤에서 앞으로): 무기(좌측)/방패(우측) → 신발 → 하의 → 상의 → 몸(피부, 원형) → 머리 →
장신구1(좌상단) → 장신구2(우상단).

- `shoes`: 위치 top 84%, 가로 36%, 세로 6%
- `pants`: 위치 top 66%, 가로 40%, 세로 16%
- `top`: 위치 top 46%, 가로 46%, 세로 22%
- `body`: 위치 top 8%, 가로/세로 38% (원형)
- `head`: 위치 top 2%, 폰트 크기 = 캐릭터 크기의 26%
- `weapon`: 위치 top 45%, left 4%, 폰트 크기 28%
- `shield`: 위치 top 45%, right 4%, 폰트 크기 28%
- `accessory1`: 위치 top 30%, left 8%, 폰트 크기 18%
- `accessory2`: 위치 top 30%, right 8%, 폰트 크기 18%

실제 아트로 교체할 때 이 비율을 그대로 유지할 필요는 없습니다 (실제 그림은 이모지보다 훨씬 디테일이
많을 테니 캔버스/좌표 시스템을 다시 설계하는 게 자연스러울 수 있음) — 다만 "몸 위에 옷을 입히고,
그 위에 머리를 얹고, 좌우로 무기/방패를 든" 레이어 순서와 대략적인 상대 위치는 참고용으로 유지하면
기존 조합(어떤 옷+어떤 무기를 같이 입어도 안 어색한 것)이 계속 자연스럽게 성립합니다.

## 6. 브랜드 색상 (참고용 — 캐릭터 아트가 UI와 안 부딪히게)

앱은 라이트/다크 모드 + 5가지 강조색 테마를 지원합니다 (사용자가 설정에서 고름):

- 퍼플(기본) `#6f5bd3` / 핑크 `#d1487a` / 블루 `#3b7dd8` / 그린 `#6b8e4e` / 오렌지 `#d9662f`

캐릭터 자체가 이 색에 맞출 필요는 없지만(피부/옷 색은 유저가 고르는 것이므로), 상점 UI·버튼·테두리
등은 이 색들을 쓰고 있으니 캐릭터 아트의 전반적 채도/톤이 너무 튀지 않게 참고하면 좋습니다.

## 7. 스타일 방향 (제안 — 확정 아님, 실제 결정은 아트 작업 시점에)

- 가족 전연령용이라 귀엽고 친근한 톤 권장 (예: SD/치비 스타일 마스코트). 폭력적이지 않게 — "검"도
  장식품으로만 쓰이지 실제 전투가 없다는 걸 감안해서 위협적이지 않은 느낌으로.
  귀여운/장난감 같은 조형이면 다른 슬롯 조합과도 잘 어울릴 것.
- 슬롯이 서로 독립적으로 조합되므로 (몸 4종 × 배경 4종 × 상의 4종 × ... ) **레이어드 스프라이트**로
  제작하는 걸 권장 — 하나의 완성된 캐릭터 그림이 아니라, 슬롯별로 분리된 투명 배경 PNG를 겹쳐서
  어떤 조합이든 자연스럽게 합성되게. (지금 코드가 정확히 이 구조 — 슬롯별 독립 레이어.)
- 배경(`background`)은 정사각형을 꽉 채우는 평면적인 배경 아트(하늘/노을/밤하늘/민트 등 지금
  이름 참고), 캐릭터 본체보다 뒤 레이어.

## 8. 산출물 형식 요구사항

- **PNG, 투명 배경** (body/top/pants/shoes/head/weapon/shield/accessory1/accessory2 — `background`
  슬롯만 예외로 불투명 정사각형).
- **정사각형 캔버스, 통일된 해상도** 권장 (예: 전부 512×512에 슬롯별 레이어를 같은 좌표계로 정렬) —
  그래야 클라이언트에서 슬롯별로 절대 위치 지정(`position: absolute`)만으로 겹쳐 그릴 수 있습니다.
  지금 코드도 이 방식(부모 컨테이너 기준 `top`/`left` % 배치)을 쓰고 있습니다.
- **파일명 규칙 제안**: `{slot}_{item_slug}.png` (예: `head_crown.png`, `weapon_sword.png`,
  `body_skin_default.png`) — `shop_items.key`처럼 영문 슬러그를 만들어서 DB의 새 `sprite_key`
  값과 파일명을 일치시키면 매핑이 쉬워집니다. (`shop_items`에 이미 `key` 컬럼이 있지만 지금은
  칭호(title_condition)에만 채워져 있고 구매형 아이템은 비어 있음 — 파일명 매핑을 위해 구매형
  아이템에도 `key`를 채우는 걸 권장.)
- 아이템 34종(포인트 상점) + 3종(타이쿤 한정) = **총 37종의 슬롯별 이미지**, 그중 "없음/기본"류
  (민머리, 맨손, 방패 없음 등)는 실제로 아무것도 안 그리는 상태를 그대로 유지해도 되고, 원한다면
  "빈 슬롯" 느낌을 살짝 살리는 그림으로 대체해도 됩니다 (필수 아님).
