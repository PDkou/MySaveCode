# 핵심 앱 기능 설계 문서 (역산 스펙, 2026-08 작성)

`GAMIFICATION_DESIGN.md`가 포인트/XP/상점/칭호/타이쿤 같은 게임화 시스템의 설계 근거를 담은
문서라면, 이 문서는 그 나머지 -- **퀘스트(할일) 관리, 가족방, 알림, 캘린더/사진첩, 설정** 등
코어 앱 기능 -- 을 다룹니다.

이 두 문서 다 "미리 설계하고 나서 구현"이 아니라 **대화로 기능을 하나씩 추가하면서 코드가 먼저
생겼고, 이 문서는 그 코드를 거꾸로 읽어서 스펙으로 정리한 것**입니다. 그래서 "왜 이렇게
동작해야 하는가"보다 "지금 실제로 어떻게 동작하는가"에 가깝고, 코드가 바뀌면 이 문서도 같이
갱신해야 의미가 있습니다.

## 목차

1. 계정 / 인증
2. 가족방 (family / personal / business, 멀티 가족방)

4. 퀘스트 -- 배정 방식 3종과 스테이킹
5. 퀘스트 -- 완료 플로우 (2단계 보고/승인, 반려, 재오픈)
6. 퀘스트 -- 반복
7. 퀘스트 -- 자동 유찰/삭제
8. 대시보드 (필터/검색/일괄작업/고정/실행취소)
9. 댓글
10. 템플릿
11. 캘린더 / 사진첩
12. 알림 (인앱 벨 + 푸시)
13. 설정
14. 회사방 전용 -- CSV 리포트
15. PWA
16. 데이터 모델 요약
17. 테스트 체크리스트

## 1. 계정 / 인증

- 이메일+비밀번호 회원가입/로그인 (Supabase Auth). 가입 시 표시 이름을 필수로 받고,
  기기 언어(`navigator.language`)로 `preferred_language`(ko/ja) 기본값을 정함.
- 비밀번호 재설정: 이메일로 링크 발송(`sendPasswordReset`) → `/reset-password` 페이지에서
  새 비밀번호 설정(`updatePassword`).
- 로그인 세션은 Supabase가 자동 갱신하며(`onAuthStateChange`), **같은 유저 id로의 세션
  갱신은 다시 프로필을 안 불러옴** -- 탭 전환/포커스 복귀마다 전체 화면이 로딩 스피너로
  깜빡이는 걸 막기 위한 장치 (`AuthContext.tsx`).
- 프로필(`profiles` 테이블)은 계정 전역 정보: 표시 이름, 아바타 사진, 생일(선택,
  "생일 선물" 칭호용), 선호 언어. `auth.users` insert 트리거(`handle_new_user`)가 자동 생성.
- 아바타 사진: 업로드 시 정사각형으로 드래그/줌 크롭 후 Storage에 저장, 이전 사진은
  베스트에포트로 삭제.

## 2. 가족방 (family / personal / business, 멀티 가족방)

- 방 종류는 `families.room_type`: `'family'` 또는 `'business'` 두 가지 뿐이고, **"개인방"은
  별도 room_type이 아니라 그냥 멤버가 1명인 family 방**입니다. 게임화 로직(스테이킹 필요 여부,
  배정 방식 판정 등) 전체가 `family_members` 카운트 기준으로 분기하지 `room_type`을 안 봅니다
  -- `room_type`을 보는 건 오직 CSV 리포트 노출 여부(14장) 뿐.
- 한 유저가 **여러 가족방에 동시에 속할 수 있음** (예: 우리집 + 회사방). `FamilyContext`가
  전체 목록(`families`)과 "지금 보고 있는 방"(`family`)을 따로 관리하고, 마지막으로 본 방을
  `localStorage`에 기억했다가 다음 로그인 때 복원. 헤더의 방 이름을 눌러 다른 방으로 전환
  가능(`FamilySwitcher`).
- 새 방 만들기: 이름 + 종류(family/business) 지정, 초대 코드 자동 생성. 첫 가입/생성 시
  시작 포인트 지급(`create_family_room`/`join_family_room` 안에서).
- 방 참여: 초대 코드 직접 입력, 또는 QR코드 스캔(`InviteQrModal` -- 코드가 아니라
  `?joinCode=` 쿼리파라미터 붙은 가입 링크를 인코딩해서, 스캔한 기기에서 가입 폼에
  자동으로 채워짐).
- 멤버 관리(`FamilyMembersModal`): 멤버 목록(이름/사진), 방 나가기, (자신이 아닌) 멤버
  추방, 초대 코드 재발급. 이 사람 이름은 방마다 다르게 표시 가능 -- `family_members.display_name`
  (방별 오버라이드)이 있으면 그걸, 없으면 `profiles.display_name`(계정 전역 기본값) 사용.
- 방 이름은 언제든 수정 가능 (`renameFamily`, `EditFamilyNameModal`).

## 3. 퀘스트 -- 생성/수정/삭제

- 필드: 제목(필수), 상세설명(선택), 담당자(0명 이상 다중 선택), 마감일시(선택),
  시작일시(선택, "예정" 표시용), 반복 주기, 스테이크 포인트.
- 생성/수정 모두 단일 RPC(`create_task`/`update_task`) 하나로 처리 -- insert를 여러 번
  나눠 하면 모바일 네트워크 끊김 때 "생성은 됐는데 실패로 보이는" 문제가 생겨서, 트랜잭션
  하나로 묶음.
- 다인원 방(2명 이상)에서는 **공짜 요청이 없음** -- 최소 5포인트를 걸어야 하고, 생성 시점에
  즉시 차감(잔액 부족하면 `insufficient_points` 에러). 1인방은 스테이킹 자체가 무의미해서
  0으로 강제.
- 삭제는 어느 멤버나 가능. 대시보드에서 지우면 **5초간 실행취소 가능한 유예 시간**을 두고,
  그 사이엔 그냥 화면에서만 숨겨질 뿐 실제 DB 삭제는 5초 뒤 커밋됨 (`TasksContext`의
  `requestDelete`/`undoPendingDelete`).
- 고정(pin): 중요한 퀘스트를 목록 상단에 고정. 이 컬럼만 클라이언트가 직접
  업데이트 가능하도록 grant가 좁혀져 있음(다른 컬럼은 전부 RPC를 거쳐야 함, PostgREST로
  직접 패치 못 하게).

## 4. 퀘스트 -- 배정 방식 3종과 스테이킹

배정 방식은 별도 컬럼이 아니라 **담당자 수를 보고 그때그때 판정**합니다
(`task_assignees` 행 개수 vs 방 전체 인원 수):

| 배정 방식 | 조건 | 완료 시 지급 |
|---|---|---|
| 선착형 (first_come) | 담당자 0명(=누구든 먼저 처리) | 완료한 사람에게 스테이크 전액 + XP. 등록자 본인이 먼저 처리하면 명성(XP) 없이 스테이크만 돌려받음 |
| 특정인 지정 (specific) | 담당자 1명 이상, 전체 인원 미만 | 지정된 사람이 완료 시 스테이크 전액 + XP + 등록자에게 스테이크의 10% 보너스(스테이크 10 이상일 때만). **등록자 본인이 본인을 지정해서 완료한 경우엔 스테이크만 환급, XP/명성 없음** (자기 자신에게 의뢰하는 어뷰징 방지) |
| 모두형 (everyone) | 담당자 수 = 방 전체 인원(또는 0명 미만 특수) | 스테이크를 담당자 수만큼 균등 분배, 전원 XP 지급 |

- "이 완료가 랭킹(포인트/스트릭/칭호)에 반영되는가"는 `finalize_task_completion`(서버)과
  `questCountsTowardRanking()`(클라이언트, 주간 리포트용)가 같은 규칙을 따로 구현: 1인방은
  항상 카운트, 모두형/무담당은 항상 카운트, 특정인·선착형은 **등록자 ≠ 완료자일 때만** 카운트.
- 반려/재오픈된 퀘스트를 완료 후 다시 열면(`reopen_task`) 지급됐던 포인트/XP/스트릭/칭호
  달성 카운트를 되돌림 -- 이미 써버린 포인트가 있으면 0까지만 회수(마이너스로 안 내려감).

## 5. 퀘스트 -- 완료 플로우 (2단계 보고/승인, 반려, 재오픈)

완료가 **즉시 확정**되는지 **등록자 승인이 필요한지**는 이 규칙으로 판정
(`report_task_completion`):

> 방 인원이 2명 이상 **이고** (담당자 수 = 전체 인원 **이거나** 등록자 ≠ 완료자) 라면
> 승인 필요.

- 즉시 확정되는 경우 (1인방, 또는 등록자 본인이 본인 지정/선착 건을 스스로 완료): 완료
  버튼 누르는 즉시 `status='done'`, 지급까지 한 트랜잭션 안에서 끝남. 화면엔 즉석
  축하 화면(포인트/레벨업/스트릭/새 칭호)이 뜸 -- **단, 실제로 XP가 오른 경우에만**. 위
  표에 나온 "등록자 본인 셀프 완료"는 스테이크만 환급되고 XP는 안 오르므로 축하 화면
  자체를 안 띄움 (2026-08 수정 -- 예전엔 스테이크 환급을 포인트 획득처럼 잘못 보여줬었음).
- 승인 필요한 경우: `status='pending_confirmation'`으로 바뀌고 지급은 아직 안 됨. 등록자가
  확인(`confirm_task_completion`, 지급 실행) 또는 반려(`reject_task_completion`, 그냥
  `open`으로 되돌림, 지급 없음) 선택. 완료자는 자기가 화면을 안 보고 있을 수도 있어서(등록자가
  나중에 승인), 지급은 완료자가 **다음에 앱을 열 때** `useUnseenCelebration` 훅이 "아직
  못 본 지급 내역"을 찾아서 대신 축하 화면을 띄워줌. `reputation_awarded=true`인 지급만
  이 대상 -- 등록자 셀프 완료류는 여기서도 제외.
- 완료 시 사진/메모 첨부 가능(`completion_note`/`completion_photo_path`), 캘린더/사진첩에
  노출됨.

## 6. 퀘스트 -- 반복

- 반복 주기: 매일/매주(요일 지정 가능)/매월. 완료(정상 완료든 뒤에서 설명할 자동 유찰이든)
  시점에 다음 회차를 자동 생성(`spawn_next_recurrence`) -- 제목/설명/담당자 그대로,
  마감일시만 주기만큼 밀어서.
- 다인원 방이면 **다음 회차도 새로 스테이킹** -- 이전에 낸 스테이크를 재활용하지 않고,
  등록자 잔액에서 다시 차감(잔액 부족하면 있는 만큼만).
- 시작일시(`starts_at`)가 있던 원본이면 다음 회차도 같이 밀어서 새로 계산, 없던 원본이면
  다음 회차도 시작일시 없음.

## 7. 퀘스트 -- 자동 유찰/삭제

- 매시 정각 cron(`sweep_expired_tasks`, pg_cron)이 돌면서:
  1. **마감일이 지난 `open` 퀘스트**(아무도 완료 보고를 안 한 것)를 `failed`로 바꾸고,
     걸려있던 스테이크를 등록자에게 환급. 반복 퀘스트면 이때도 다음 회차를 생성함(6장)
     -- 안 그러면 한 번 놓친 순간 반복이 영구히 끊기는 버그였음 (2026-08 수정).
  2. `pending_confirmation` 상태(누가 완료 보고는 했지만 아직 승인 안 된 것)는 기한이
     지났어도 안 건드림 -- 일이 일어나긴 했으니 "실패"가 아니라 승인/반려로 풀어야 함.
  3. **3일 지난 `failed` 퀘스트는 완전히 삭제** -- 그 전까진 "안 됐던 기록"으로 화면에 남아있음.
- 마감일(`due_at`)이 아예 없는 퀘스트는 영원히 유찰 안 됨 ("기한 없음" 의도적으로
  열어둠).

## 8. 대시보드 (필터/검색/일괄작업/고정/실행취소)

- 상태 탭: 진행 중 / 완료 / 전체. "내 담당만" 체크박스로 좁히기 가능.
- 제목 검색.
- 선택 모드: 여러 퀘스트 체크해서 한 번에 완료 처리(메모/사진 없이, 빠른 일괄완료 -- `completeTasks`)
  또는 삭제.
- 새로고침 버튼 + Supabase Realtime 구독으로 다른 멤버의 변경사항이 실시간 반영.
- 상단에 레벨/포인트/스트릭 요약, 장착한 칭호/뱃지 네임플레이트(`TitleFrame`/`badge-chip`),
  주간 완료 개수, 다음 레벨까지 진행률 바.

## 9. 댓글

- 퀘스트 하나에 자유롭게 남기는 진행상황/답글 스레드 (`task_comments`) -- 완료 기록에
  한 번만 남는 `completion_note`와 별개로, 언제든 몇 개든 남길 수 있음(이모지 하나짜리
  리액션도 허용).
- 누구나 남길 수 있지만 **본인이 쓴 댓글만 본인이 삭제** 가능 (퀘스트 자체는 아무나
  지울 수 있는 것과 다른 기준 -- "남의 말"이라서).
- 새 댓글이 달리면 관련자(등록자+담당자, 작성자 본인 제외)에게 인앱 알림 + 푸시.

## 10. 템플릿

- 자주 쓰는 요청 내용(제목/설명/반복주기/담당자)을 저장해뒀다가 새 퀘스트 만들 때
  바로 불러오기 (`task_templates`, 방 전체 공유).

## 11. 캘린더 / 사진첩

- **캘린더**: 월별 그리드, 날짜별 퀘스트 개수 뱃지(진행중이면 강조색, 전부 완료면 흐리게),
  완료 사진이 있으면 그 날짜 칸에 작은 썸네일. 날짜 클릭 시 그날 마감인 퀘스트 목록.
- **사진첩**: 완료 사진이 첨부된 퀘스트를 최신순으로 그리드 표시, 클릭하면 해당 퀘스트
  상세로 이동.

## 12. 알림 (인앱 벨 + 푸시)

**인앱 알림 벨** (`NotificationBell`/`useNotifications`): 최근 활동 로그(`task_activities`)와
댓글(`task_comments`)을 실시간 구독해서, "나와 관련 있는"(내가 등록했거나 담당인 퀘스트에
남이 한 행동) 것만 걸러서 보여줌. 벨을 닫을 때(연 순간이 아니라) "여기까지 봤다"고 기록해서
다음에 열면 새 것만 남음. 배지 숫자로 안 읽은 개수 표시.

**푸시 알림** (Web Push, Edge Function `send-due-reminders` -- 실제 배포명은 `rapid-service`):

| 종류 | 트리거 | 대상 |
|---|---|---|
| 마감 임박 | 마감 5분 전 (1분마다 도는 cron, 놓친 것 15분까지 소급 확인) | 담당자 |
| 기한 초과 | 마감 60분 지났는데 아직 open (같은 cron) | 담당자 + 등록자 |
| 생성/배정 | 퀘스트 생성 직후 (DB 트리거) | 담당자 |
| 완료/재오픈/댓글 | 해당 행동 직후 (DB 트리거) | 등록자 + 담당자(행위자 본인 제외) |
| 주간 리포트 | 매주 1회 (cron) | 방 전체(옵트인) |

- 각 알림 종류는 사용자가 개별적으로 켜고 끌 수 있음(`notification_prefs`, 벨 패널 안
  접이식 섹션). 설정 행이 없으면 "전부 켜짐"으로 취급 -- 대부분의 유저는 안 건드리니까.
- 마감/기한초과 알림은 "이 마감시각에 대해 이미 보냈는지"를 컬럼에 기록해서 중복 방지.
  같은 분에 cron이 겹쳐 도는 경우까지 대비해 **먼저 원자적으로 선점(claim)한 실행만 발송**
  (2026-08 수정 -- 전엔 발송 후 표시라 겹치면 중복 발송 가능성 있었음).
- 언어: 각 수신자의 `preferred_language`에 맞춰 한국어/일본어 메시지 발송.

## 14. 회사방 전용 -- CSV 리포트

## 15. PWA

- 홈 화면에 설치 가능(manifest + 서비스워커). 설치 안내 배너를 자체 구현해서 안 닫으면
  다시 보여줌.
- 홈 화면 앱 아이콘에 "내 담당 진행중 퀘스트 개수" 배지 표시 (Badging API 지원 브라우저만 --
  iOS Safari는 미지원이라 조용히 no-op).
- 마지막으로 보던 라우트를 기억했다가, OS가 백그라운드에서 앱을 죽였다 재시작할 때
  (Android 사진 선택 중 등) 시작 화면(`/`) 대신 원래 있던 화면으로 복귀.
- **오프라인 모드는 없음** -- 네트워크 끊기면 각 화면에서 요청 실패가 그대로 노출됨(무한
  로딩으로 멈추지 않는 정도까지만 챙김). 서비스워커는 앱 셸(정적 파일)만 프리캐시하고,
  API 호출은 전부 매번 네트워크로 나감.

## 17. 테스트 체크리스트

`README.md` 5장(계정 2개 실사용 점검)·6장(RLS 보안 점검)에 이미 있는 것과 겹치지 않게,
**기능별로 실제 사용하면서 확인할 것들**만 정리했습니다. 체크 안 된 항목은 이번에 문서
쓰면서 코드로만 확인했고 아직 실기기로 검증 안 한 것들입니다.

### 퀘스트 배정/완료 (제일 버그가 많이 나왔던 영역)
- [ ] 1인방에서 퀘스트 생성 → 완료 → 즉시 축하화면 + 포인트/XP 반영
- [ ] 다인원 방, 본인이 등록+본인 지정 완료 → **축하화면 안 뜸**, 포인트 잔액 변화 없음 (5장 방금 수정)
- [ ] 다인원 방, A가 등록해서 B를 지정 → B가 완료 보고 → `pending_confirmation` 상태 확인 →
      A가 승인 → B가 다음에 앱 열었을 때 축하화면이 뜨는지
- [ ] 위 상황에서 A가 반려 → 퀘스트가 `open`으로 돌아오고 아무 지급도 없는지
- [ ] 모두형 퀘스트, 담당자 여러 명이 각자 완료 → 스테이크가 인원수만큼 나뉘어 지급되는지
- [ ] 선착형 퀘스트, 등록자 본인이 먼저 잡음 → 스테이크만 환급, XP 없음
- [ ] 완료된 퀘스트 재오픈 → 포인트/XP/스트릭이 정확히 되돌아가는지 (특히 그 사이에
      포인트를 다 써버린 상태에서도 마이너스로 안 내려가는지)

### 반복 퀘스트
- [ ] 매일 반복 퀘스트를 기한 내 완료 → 다음날로 다음 회차 자동 생성
- [ ] 매일 반복 퀘스트를 기한 넘겨서 방치 → `failed` 처리 + 스테이크 환급 + **다음 회차도
      자동 생성**되는지 (2026-08 수정, 실사용 미확인)
- [ ] 매주 특정 요일 반복이 정확한 다음 요일로 계산되는지

### 알림
- [ ] 마감 5분 전 푸시가 실제로 오는지, 두 번 안 오는지
- [ ] 기한 초과 알림이 담당자뿐 아니라 등록자에게도 오는지
- [ ] 알림 종류별 토글을 끄면 정말 그 종류만 안 오는지
- [ ] 인앱 알림 벨 배지 개수가 실제 안 읽은 개수와 맞는지, 닫으면 다음에 새 것만 남는지

### 멀티 가족방
- [ ] 두 방에 동시에 속한 계정으로 방 전환 시 데이터가 확실히 섞이지 않는지 (포인트,
      퀘스트 목록, 알림 전부 방 단위로 분리되는지)
- [ ] 회사방에서만 CSV 버튼이 보이는지, family방에선 안 보이는지

### 회사방 CSV 리포트
- [ ] 실제로 다운로드한 CSV를 엑셀에서 열었을 때 한글이 안 깨지는지
