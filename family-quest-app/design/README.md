# 디자인 필요 항목 인덱스

이 앱(Family Quest)의 기능은 대부분 구현·배포·실사용 중이지만, 코드로 직접 그린 placeholder에
머물러 있어 실제 "디자인 작업"이 필요한 영역이 몇 군데 있습니다. 이 폴더는 그 영역을 카테고리별
문서로 나눠 정리한 것입니다 — 각 문서는 "지금 뭐가 placeholder인지 / 실제로 뭘 만들어야 하는지 /
코드 어디서 쓰이는지"를 담고 있어서, 디자이너에게 그대로 전달하거나 직접 에셋을 만들 때 참고용으로
쓸 수 있습니다.

## 카테고리

| 문서 | 요약 상태 |
|---|---|
| [`character-art.md`](./character-art.md) | 캐릭터가 CSS 도형 + 이모지 조합으로만 표현됨. 인수인계 스펙(색상값/슬롯 배치)은 완성, 실제 이미지 제작은 미착수 |
| [`gamification-iconography.md`](./gamification-iconography.md) | 뱃지 7종은 기본 이모지 그대로, 칭호 76종은 시각 요소가 아예 없음(텍스트만) |
| [`branding-app-icon.md`](./branding-app-icon.md) | 앱 아이콘/브랜드 심볼이 코드로 픽셀을 직접 찍어 그린 원+집 모양 도형 — 실제 로고 디자인 없음 |
| [`ui-visual-system.md`](./ui-visual-system.md) | 색상 테마/타이포는 갖춰져 있으나, 온보딩·빈 상태 등 일러스트 요소는 최소한의 SVG 도형뿐 |

## 우선순위에 대한 참고

- **가장 체감이 큰 것: 캐릭터 아트.** 상점/캐릭터 커스터마이징이 게임화의 핵심 기능인데, 지금은
  색 블록 + 이모지 조합이라 다른 기능들의 완성도에 비해 눈에 띄게 떨어집니다.
- **가장 손이 적게 드는 것: 브랜딩/앱 아이콘.** 심볼 하나만 확정하면 기존 `generate-icons.cjs`
  파이프라인(사이즈별 PNG 생성)은 그대로 재사용 가능합니다.
- 뱃지/칭호 아이콘, 빈 상태 일러스트 등은 있으면 완성도가 올라가지만 기능 자체가 막혀 있는 건
  아니라 우선순위가 상대적으로 낮습니다.

## 문서 작성 방식

각 문서는 실제 코드(컴포넌트/에셋 생성 스크립트)를 근거로 "지금 상태"를 적었고, 추측성 내용은
넣지 않았습니다. 코드가 바뀌면(예: 캐릭터 실제 아트가 들어가면) 이 문서들도 함께 갱신해야 합니다.

## AI 이미지 생성 프롬프트

2026-07-30에 사용자가 확정한 레퍼런스 시트(16비트 픽셀아트 치비 RPG 스타일 — "FAMILY QUEST" 로고,
헤어/무기/방패 아이콘 줄, 조립된 캐릭터 5종, 화폐/상태 아이콘 줄, 배경 카드 2장) 기준으로 4개 문서
전부에 **동일한 스타일 고정(Style Lock) 문단 + 항목별 프롬프트**를 추가했습니다
(`character-art.md`/`gamification-iconography.md`/`branding-app-icon.md`/`ui-visual-system.md`
전부 "AI 이미지 생성 프롬프트" 절 참고). 스타일 고정 문단은 4개 문서에 글자 하나까지 동일하게
복사되어 있습니다 — 어느 문서를 먼저 열어서 작업하든 같은 그림체가 나오도록 하기 위함이니, 문단을
고칠 때는 4곳 전부 같이 고쳐야 합니다.
