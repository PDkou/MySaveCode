> 자체는 안 되고 예전 방식(포즈마다 여러 장 새로 생성)으로 이 문서의 나머지 요청(포즈 종류
> 확장)만 채워졌을 가능성이 있습니다. 실제 화면에서 자연스럽게 움직이는지 확인 후, 리깅
> 전환이 여전히 필요하면 이 문서 요청이 유효합니다. `src/lib/featureFlags.ts`의
> `GAME_FEATURES_ENABLED`는 이 확인이 끝나기 전까지 계속 꺼둔 상태입니다.

**v7의 방향 전환("도트그래픽 포기, 플랫 일러스트로")까지는 맞았지만, 제작 방식은
여전히 "포즈마다 AI로 새로 그리기"에 머물러 있었습니다. 이 방식 자체가 아래
문제들의 근본 원인이므로, v8부터는 제작 방식을 바꿉니다: 캐릭터를 매 포즈 새로
그리는 대신, 하나의 원화를 부위별로 나눠 그 조각들을 코드에서 움직이는 방식
(2D 컷아웃/리그 애니메이션)으로 전환합니다.**

## 0. v7에서 무엇이 틀렸었나

- **도구 아이콘(도트)과 캐릭터·배경·오염물(플랫)을 나눈 것**: 이렇게 하면 방
  안에 실제로 배치되는 도구가 배경/캐릭터랑 화풍이 안 맞아서, 계속 지적받았던
  "아이템이 배경과 동화되지 않는 문제"가 그대로 재발합니다.
- **포즈마다 새로 생성하는 방식**: AI가 매번 새로 그리다 보니 포즈마다 캐릭터
  크기가 미묘하게 다르고, 얼굴·머리카락이 조금씩 바뀌고, 손에 든 도구 모양이
  깨지고, 대기 상태와 청소 상태의 캐릭터 위치가 어긋나는 문제가 반복됐습니다
  (지난 라운드 검수에서 8프레임 중 여러 장이 완전 중복이거나, 프레임 간 형태가
  미묘하게 녹아내리는 것도 이 방식의 한계였습니다).

## 1. 새 공식 기준: 컷아웃(부위 분리) 애니메이션

캐릭터를 포즈별 완성 그림으로 여러 장 요청하지 않습니다. 대신 **캐릭터 원화 1개를
아래 부위로 나눠서** 요청합니다. 코드 쪽에서 이 부위들을 겹쳐 놓고 회전/이동
변형(CSS transform)으로 움직여서 포즈를 만듭니다 — 몸통/얼굴/다리는 모든 포즈에서
**완전히 같은 파일**을 재사용하므로, 포즈마다 캐릭터가 달라지는 문제 자체가
구조적으로 없어집니다.

| 부위 파일 | 설명 |
|---|---|
| `character-head.png` | 머리(머리카락 포함), 눈 제외 |
| `character-eyes-open.png` / `-half.png` / `-closed.png` | 눈 3종 (같은 위치에 겹쳐서 교체 — 깜빡임용) |
| `character-torso.png` | 몸통 (작업복 상의 포함) |
| `character-arm-left.png` | 왼팔 (거의 고정, 미세한 움직임만) |
| `character-arm-right-idle.png` | 오른팔 — 대기 상태 |
| `character-arm-right-broom.png` | 오른팔 — 빗자루 쥔 상태 |
| `character-arm-right-mop.png` | 오른팔 — 걸레 쥔 상태 |
| `character-arm-right-holding.png` | 오른팔 — 새 도구를 들어 보이는 상태 |
| `character-legs.png` | 다리/발 (고정, 모든 포즈에서 발 위치 동일) |
| `broom-tool.png` / `mop-tool.png` | 손에 들리는 도구 자체 (팔 레이어 위에 겹침) |

**요구사항**:
- 모든 부위는 **같은 캔버스 크기, 같은 중심축 기준**으로 그려서 겹쳤을 때 이음매
  없이 맞아야 합니다 (팔이 몸통에서 시작하는 위치, 다리가 몸통과 만나는 위치가
  부위마다 어긋나면 안 됨).
- 눈 3종은 위치·크기가 완전히 같아야 하고 머리 위에 정확히 겹쳐야 합니다.
- 팔 변형(대기/빗자루/걸레/들어보이기)은 어깨 관절 위치가 전부 동일해야 코드에서
  회전시켰을 때 자연스럽습니다.
- 대기 모션(호흡/깜빡임)과 청소 동작(팔 회전) 둘 다 **발 위치가 절대 변하지
  않아야** 합니다 — 다리 레이어가 고정이므로 자연히 지켜집니다.

**표정/청소 액션 표현 방법이 이렇게 바뀝니다**:
- 대기: 몸통을 CSS로 아주 살짝 상하로 움직이고, 눈 레이어를 가끔 `-closed.png`로
  짧게 교체 (깜빡임). 완성 그림을 여러 장 요청할 필요 없음.
- 빗자루질/걸레질: 오른팔 레이어를 해당 도구 버전으로 바꾸고, 어깨를 중심으로
  CSS 회전 애니메이션으로 좌우로 흔듦. 도구 자체(`broom-tool.png`)는 팔 끝에
  고정된 위치로 같이 회전.
- 새 도구 발견: 오른팔을 `-holding.png`로 바꾸고 해당 도구 아이콘을 손 위에 표시.

## 2. 방 배경 — 시간대별 통짜 그림 대신 레이어 분리

지금까지 방마다 "아침/오후/저녁/밤" 4장을 통째로 새로 그리다 보니 매번 가구
배치나 디테일이 미묘하게 달라지는 문제가 있었습니다. v8부터는:

| 레이어 | 설명 | 시간대별로 몇 장? |
|---|---|---|
| 방 기본 배경 | 벽/바닥/가구 — 시간대와 무관하게 항상 같음 | 방마다 1장 |
| 창밖 풍경 | 창문 안에 들어갈 하늘/풍경만 별도 이미지 | 시간대별 1장 (방과 무관하게 재사용 가능하면 더 좋음) |
| 조명 | 시간대에 따른 색 톤(아침은 밝고 노란빛, 밤은 어둡고 푸른빛) | **그림 아님** — 코드에서 CSS 색 오버레이로 처리 |

즉 방 하나당 필요한 그림은 "기본 배경 1장 + (공용일 수 있는) 창밖 풍경 몇 장"뿐이고,
조명 변화는 별도 그림 없이 코드에서 처리합니다. 방 5개 × 창밖 4종 = 배경 관련
그림이 지금보다 훨씬 적게 필요합니다.

## 3. 도구 아이템 — 두 가지 용도로 분리

| 용도 | 스타일 | 파일 |
|---|---|---|
| 상점/업그레이드 목록의 작은 아이콘 | **기존 도트 아이콘 그대로 사용** (의도적인 레트로 느낌으로 유지) | 지금 있는 `{tool_id}.png` (변경 없음) |
| 방 안에 실제로 배치되는 아이템 | **새로 제작 — 캐릭터/배경과 같은 플랫 스타일** | 새 파일 (예: `{tool_id}-scene.png`) |

지금까지의 "아이템이 배경과 안 어울림" 문제는 정확히 이 구분이 없어서
생겼습니다 — 상점 아이콘은 도트여도 상관없지만, 방 안에 놓이는 순간에는 캐릭터·
배경과 같은 화풍이어야 합니다.

## 4. 유지되는 것 / 새로 제작하는 것 (재확인)

**코드/시스템 그대로 유지**: 게임 로직, 아이템 이동 경로, 업적, 피버, 시간대 전환
코드(`cleanerTimeOfDay()` 등) — 이번 변경은 전부 아트 레이어 교체이지 게임 로직
변경이 아닙니다.

**새로 제작**: 캐릭터 부위 세트 (1번), 방 기본 배경 + 창밖 풍경 (2번), 방 배치용
아이템 플랫 버전 (3번). 기존 `actor-v8`, `backgrounds-time-v3`, `clutter-v4`는
이 부위 분리 방식으로 대체되므로 더 이상 기준이 아닙니다.

## 5. 스타일 스펙 (v7과 동일 — 유지)

- 두꺼운 외곽선 (전체 통일된 두께)
- 평평한 색면 (밝은 톤 1개 + 그림자 톤 1개 정도, 심한 그라디언트 금지)
- 사실적 텍스처/포토리얼리즘 금지, 단순하고 읽기 쉬운 형태
- 기존 캐릭터의 얼굴/눈 색/머리 모양/비율/빨간 작업복 유지

## 6. 바로 쓸 수 있는 프롬프트 예시

캐릭터 부위 (예: 오른팔 빗자루 버전):

```
Same chibi character as the reference (same face, same hairstyle, same
proportions, same red overalls, same flat cartoon illustration style --
thick uniform outline, flat color fields, minimal 1-2 tone shading, no
photorealism). Draw ONLY the right arm, bent as if gripping a broom
handle, isolated on a transparent background, same canvas size and
shoulder-joint position as the reference body so it aligns perfectly
when layered on top.
```

방 배경 (예: 거실 기본):

```
Simple flat cartoon illustration of a cozy living room interior --
thick uniform outline, flat color fields, minimal shading, no
photorealistic texture. Include a window opening left as plain empty
space (the view will be layered in separately). Furniture and layout
should stay consistent with [기존 참고 이미지].
```
