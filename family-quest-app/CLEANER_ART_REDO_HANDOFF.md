# 집안일 클리커 — 아트 재작업 인수인계 문서 v4 (GPT/이미지 생성 도구용)

**이 문서는 이전 세 문서(`CLEANER_ART_HANDOFF.md`, `CLEANER_TOOL_ICONS_HANDOFF.md`,
`CLEANER_CHARACTER_AND_ROOM_PROGRESS_HANDOFF.md`)로 받은 결과물을 실제로 화면에 붙이고
직접 플레이해본 뒤 나온 재작업 요청입니다.** 이전 문서들의 캐릭터/도구 아이콘 자체는
품질 기준(저해상도 원본, 락된 팔레트, 완전 불투명/투명 알파)을 통과했지만, **그 아이콘들과
같은 화면에 같이 떠 있는 다른 이미지들을 이번에 다시 검수하다가 훨씬 더 심각한 문제를
발견했습니다** — 아래 1번이 이번 재작업의 핵심입니다.

## 0. 왜 다시 요청하는가 (검수 실패 기록 — 숨기지 않고 그대로 남김)

지금까지의 검수는 **"이번에 새로 받은 파일"만** 픽셀 단위로 분석했습니다 (색상 수,
해상도, 알파 채널). 그 결과 새 파일들은 전부 기준을 통과했지만, **그 새 파일들이 실제로
같은 화면에서 무엇과 겹쳐서 보이는지는 이번에야 처음으로 직접 확인했습니다.** 그 결과:

- 방 배경의 "청소 완료(clean)" 버전 5장은 **한 번도 재작업 대상이 아니었던 기존 파일**이라
  아직도 예전 문제(색상 255~256개, 원본 해상도 627×627~1254×1254 — AI 디퓨전이 "픽셀아트
  스타일"만 입힌 매끈한 이미지)를 그대로 가지고 있었습니다. 반면 이번에 새로 받은 "더러운
  (dirty)" 버전 5장은 진짜 저해상도(128×128, 35~39색)입니다. **같은 방의 두 상태가 완전히
  다른 화풍이라, 챕터가 진행되며 크로스페이드될 때 오히려 더 부자연스럽습니다** —
  직접 렌더링해서 확인해보니, clean 레이어가 워낙 디테일이 많아서 진행도가 낮을 때도
  dirty 레이어를 거의 덮어버려 "방이 더러워 보이지도 않는" 상태였습니다.
- 어질러진 것들(clutter) 오버레이 4장(`clutter-toys.png`, `clutter-papers.png`,
  `clutter-stain.png`, `clutter-dust.png`)도 같은 문제입니다 — 색상 254~255개, 원본
  해상도 300~420px대. 이것도 한 번도 재작업 대상에 안 들어갔던 기존 파일입니다.
- 캐릭터는 대기 포즈가 딱 1장뿐이라 "숨쉬기 애니메이션"을 아무리 CSS로 다듬어도 한계가
  있습니다. 실제 플레이 피드백: "여전히 허공에 둥둥 떠 있는 것처럼 보임". 코드 쪽에서
  무게감 있는 움직임(그림자 싱크, 미세 회전)으로 어느 정도 완화했지만, 진짜 해결은 표정/
  자세가 다른 대기 포즈가 추가로 있어야 합니다.
- 걸레질 포즈는 1장짜리 정지 이미지입니다 (빗자루질은 4프레임). 탭할 때마다 두 동작이
  번갈아 나오는데, 한쪽만 애니메이션이 없어서 그 순간 유독 뻣뻣하게/멈춰 보입니다.

**앞으로 이런 문서 작업을 할 때는, 새로 받은 파일뿐 아니라 그 파일들과 같은 화면에 함께
표시되는 기존 파일도 전부 같은 기준으로 다시 검수합니다.** 이번 문서의 1번 항목이 바로
그렇게 걸러진 재작업입니다.

## 1. [최우선] 방 배경 "청소 완료" 버전 5장 재작업 — 기존 dirty 버전과 화풍 통일

### 참고 파일 (같이 첨부된 zip 안에 있음)

| 방 ID | 이번에 다시 그릴 파일 | 화풍을 맞춰야 할 기준 파일 (이미 저해상도로 완성됨) |
|---|---|---|
| `living_room` | `living-room-base-clean.png` | `living-room-base-dirty.png` (128×128, 36색) |
| `kitchen` | `kitchen-base-clean.png` | `kitchen-base-dirty.png` (128×128, 38색) |
| `bathroom` | `bathroom-base-clean.png` | `bathroom-base-dirty.png` (128×128, 36색) |
| `kids_room` | `kids-room-base-clean.png` | `kids-room-base-dirty.png` (128×128, 39색) |
| `whole_house` | `whole-house-base-clean.png` | `whole-house-base-dirty.png` (128×128, 35색) |

**요청**: 각 방의 "clean" 버전을, 같은 방의 "dirty" 버전과 **완전히 같은 원본 해상도(128
×128), 완전히 같은 팔레트 크기대(30~40색), 완전히 같은 아웃라인 두께/그림 스타일**로
다시 그려주세요. 구도(가구 배치, 카메라 앵글)는 지금의 clean 버전과 dirty 버전이 이미
서로 맞춰져 있으니 그대로 유지하고, **차이는 오직 "먼지/얼룩/어질러짐이 있는가 없는가"
뿐**이어야 합니다. dirty 버전에서 있던 먼지/거미줄/삐뚤어진 쿠션 등을 지우고 깔끔하게
정리된 상태로 그리면 됩니다.

이 5장은 게임 안에서 **같은 방 안에서 두 레이어가 CSS로 크로스페이드**됩니다(청소
진행도가 오를수록 dirty 위에 clean이 서서히 겹쳐집니다) — 그래서 두 레이어의 원본
해상도/팔레트가 다르면 크로스페이드 도중 화질이 순간적으로 바뀌는 것처럼 보입니다.
반드시 dirty 버전과 픽셀 단위로 같은 급이어야 합니다.

이 4장도 위 1번과 같은 기준(원본 저해상도, 30~40색 이내 락된 팔레트)으로 다시 그려주세요.
내용(장난감 더미/서류 뭉치/얼룩/먼지)은 그대로, 화풍만 방 배경/캐릭터/도구 아이콘과

## 3. 캐릭터 대기 포즈 베리에이션 2~3장 추가

지금 대기 포즈는 `cleaner-girl-idle.png` 1장뿐입니다. 완전히 새로운 포즈가 아니라,
**같은 서 있는 자세에서 표정/디테일만 살짝 다른 버전**을 2~3장 추가로 요청합니다 — 코드
쪽에서 몇 초 간격으로 랜덤하게 섞어 보여줄 예정이라, 자세 자체가 크게 바뀌면 오히려
어색합니다.

| # | 포즈 | 힌트 |
|---|---|---|
| 1 | 눈 감고 깜빡이는 순간 | 두 눈을 감은 표정 한 프레임 (실제 깜빡임처럼 아주 짧게 섞어 보여줄 예정) |
| 2 | 옆으로 살짝 고개 돌림 | 정면이 아니라 살짝 옆을 보는 자세, 표정은 편안하게 |
| 3 (선택) | 기지개/으쓱 | 어깨를 살짝 으쓱하거나 기지개 켜는 듯한 자세, 미소 |

기존 `cleaner-girl-idle.png`와 정확히 같은 캐릭터/같은 팔레트/같은 원본 해상도(74×96
안팎)/같은 체형 비율을 유지해야 합니다 — 다른 캐릭터처럼 보이면 안 됩니다.

## 4. 걸레질 포즈를 빗자루질처럼 다중 프레임으로

지금 `cleaner-girl-mop-1.png` 1장뿐입니다. 빗자루질(`cleaner-girl-sweep-1~4.png`, 4프레임)
과 같은 방식으로 **2~4프레임 연속 동작**으로 다시 요청합니다 — 걸레를 앞뒤로 미는 동작의
연속 스틸컷이면 됩니다. 파일명 예정: `cleaner-girl-mop-1.png` ~ `cleaner-girl-mop-4.png`
(또는 2~3프레임이면 그만큼만).

## 5. 스타일/기술 스펙 (이전 문서와 동일 — 반드시 재확인)

이전 문서들에서 이미 강조했던 조건이고, 이번에 재작업 대상이 된 방 배경/클러터 아이콘도
**전에는 이 조건을 적용받은 적이 없었던 구버전 파일**이라는 게 이번 문제의 원인입니다.
반드시 아래를 지켜서 요청하세요:

- **실제 캔버스 자체가 저해상도**여야 합니다 (고해상도로 그린 뒤 축소가 아니라, 애초에
  낮은 해상도 격자 위에 그리기). 방 배경은 128×128, 클러터는 80~120px 안팎, 캐릭터는
  74×96 안팎 — 옆에 있는 기존 기준 파일과 **같은 원본 픽셀 크기**로 맞추세요.
- **팔레트를 숫자로 못박기**: 방 배경/클러터는 30~40색 이내, 캐릭터는 16~20색 이내. 부위
  마다 밝은 톤 1개 + 그림자 톤 1개만, 그 이상 그라디언트 금지.
- 아웃라인 두께 이미지 전체에서 통일.
- 캐릭터/클러터는 완전 불투명/완전 투명 알파만 (반투명 경계 없음). 방 배경은 불투명
  이미지(알파 불필요).
- 확대 전달 시 최근접 이웃(nearest-neighbor) 방식으로만 업스케일.
- 가능하면 범용 이미지 생성 AI보다 도트아트 전용 생성 도구를 우선 시도.

## 6. 이번 재작업물 검수 기준 (참고 — 받는 쪽에서 이렇게 확인할 예정)

받은 파일은 이번엔 다음을 전부 확인합니다:

1. 파일별 원본 해상도 + 색상 수 (PIL `getcolors`) — 위 스펙 범위 안에 있는지.
2. 알파 채널 히스토그램 — 반투명(1~254) 픽셀 비율이 0%인지.
3. **같은 방의 dirty/clean 두 버전을 나란히 놓고 화풍이 실제로 같아 보이는지 육안 확인**
   (이번에 빠졌던 검증 — 앞으로는 스크립트 수치만이 아니라 항상 직접 봅니다).
4. 실제 크로스페이드 코드(진행도 0%/50%/100%)에 넣고 렌더링해서 단계별로 방이 실제로
   더러움→깨끗함으로 바뀌어 보이는지 스크린샷으로 확인.
