# Hungry Pack (가제) — 게임 기획서

## 배경 및 방향 전환 기록
- 최초안 "Lane Rush"(레인 회피 아케이드)에서 시장 조사 후 방향 전환
- 총괄마케팅 조사: 2026년 시장에서 CloverPit(슬롯머신 로그라이트, 100만 장+ 판매), Scritchy Scratchy(스크래치카드형 인크리멘탈) 등 "확률 기반 보상 + 라운드마다 상승하는 목표치 + 메타 강화" 루프를 가진 게임들이 강하게 검증되고 있음을 확인
- 단, 위 게임을 그대로 베끼지 않고 **핵심 루프만 참고해 우리만의 오리지널 컨셉으로 재설계**
- 회사명(Howling·늑대)에 맞춰 카지노/슬롯머신 테마 대신 "무리를 이끌고 겨울을 나는 사냥 서바이벌"로 재구성
  - 부가 이유: 슬롯머신을 문자 그대로 구현하면 스팀 심사에서 도박 시뮬레이션 관련 연령등급/규제 이슈가 붙을 수 있음 — 테마 변경으로 회피

## 8차 피드백 — 개발 철학 확정: Dopamine Driven Development (2026-07-21)
총괄책임자 지시: "우리 게임은 DDD를 중점적으로 개발하는 거야" → "Dopamine Driven Development" — 앞으로 모든 기능/설계 판단을 **"이게 도파민을 만드는가"**를 1순위 기준으로 평가한다는 개발 철학을 공식 채택. 이론적 근거는 `reports/2026-07-10-dopamine-mechanics-research.md`(변동 보상/니어미스 심리학, Peggle/Suika/Space Rock Breaker의 "물리적으로 눈에 보이는 불확실성" 계열, Juice 디자인 원칙)에 이미 정리돼 있음 — 이번 선언으로 그 보고서가 "참고 자료"에서 "개발 원칙"으로 격상됨.

**현재 반영 현황 감사 (총괄기획)**

이미 구현되어 이 원칙을 만족하는 것:
- 니어미스 연출(`nearMissPulse`), 연쇄 시청각 확대(`Sound.chainSpark`+`punchFov`), 파헤치기 "지켜보는 구간"(`DIG_SUSPENSE_MS` 480ms + 상승음 + 눈보라 파티클, Space Rock Breaker의 Plinko 참고 제안 그대로 구현됨), 조준 중 설렘 연출(`updateAim`의 breathe/anticipationTick), 긴장감 하트비트, 목표 게이지, 승리 시 팡파레 — 보고서 3장·6장의 세션 내(in-session) 제안 대부분 실제로 반영 완료

**아직 비어있는 영역 (보고서가 명시적으로 지적했던 곳)**:
1. ~~**세션 간 리텐션 — 현재 전혀 없음**~~ → **당일 반영 완료.** `Daily` 시스템(localStorage 기반 접속일/스트릭 추적) 추가: 강제 대기 없이 접속 즉시 그날의 보너스(정찰 +N회, 스트릭 비례 최대 +3) 지급, 하루 결석은 그레이스로 봐주고(스트릭 유지) 이틀 이상 결석해야 리셋되는 관대한 구조. 타이틀 화면에 "🔥 연속 N일째" 노출
2. **유물 상점 소프트 천장**: 나쁜 유물만 연속으로 뜨는 걸 완화할지는 여전히 미결정 (도박 규제 리스크 때문에 신중 검토 필요 — 4장 참고)
3. **정식 Juice 감사(audit)**: 걷기/파헤치기/포획/함정/성공 각 입력에 대해 "반응이 충분히 과한가"를 항목별로 점검한 적은 아직 없음 — 지금까지는 개별 기능 추가할 때마다 그때그때 얹은 것이지, 전체를 훑어본 적은 없음

다음 착수 후보는 2번(상점 소프트 천장, 총괄기획 판단 필요) 또는 3번(정식 Juice 감사) 중 총괄책임자 선택.

## 7차 피드백 — 장르 정체성 확정: 1인칭 익스트랙션 서바이벌 로그라이트 (2026-07-21)
총괄책임자 주재로 전 부서 회의 진행. 웹 프로토타입(`web_test/fps_prototype.html`)에 캠프/트레일 게이트/발자국·은신/프롤로그/온보딩까지 쌓인 뒤, "긴장감 부족·성취감 부족·스토리 부족·UI 레이아웃 문제" 지적과 함께 "장르 자체가 정해지지 않은 게 근본 원인"이라는 총괄책임자 판단 → 장르 확정을 최우선 과제로 지정.

**확정 장르: "1인칭 익스트랙션 서바이벌 로그라이트"**
- 총괄기획 분석: 지금까지 쌓아온 코어 루프(정체불명 오브젝트를 직접 파헤쳐 확인 → 캐시아웃 또는 강행 선택 → 함정이면 이번 사냥 전량 손실 → 캠프로 귀환해 다음 준비)가 구조적으로 익스트랙션 장르 문법(미지의 공간 진입 → 위험 감수하며 수집 → 한계 전에 탈출)과 정확히 일치함을 확인
- 총괄마케팅 판단: 기존 "푸시 유어 럭 카드 로그라이트" 포지셔닝은 CloverPit/Balatro가 이미 장악한 레드오션인 반면, "1인칭 익스트랙션"(Lethal Company류)은 현재 스팀에서 강세인 카테고리 — 늑대 무리 테마 + 뽑기형 블라인드 판정이라는 우리만의 각도로 이 카테고리 안에서 차별화 가능. `MARKETING.md`에 이미 4번 카피 후보("귀환할까, 계속 나아갈까")가 "익스트랙션 메커닉"을 괄호로 언급하고 있었음 — 방향 자체는 처음부터 잠재해 있었고, 이번에 정식으로 주 정체성으로 승격
- 장르가 확정되면서 회의에서 나온 나머지 지적들의 해법도 장르 문법을 따라가는 방향으로 정리됨(아직 미구현, 다음 착수 예정):
  - **긴장감 부족**: 익스트랙션 장르는 정적 확률 정보가 아니라 능동적 압박(시간/추적 위협)이 핵심 — 스킬로 함정을 회피하게는 하지 않되(기존 원칙 유지), 체류 시간이나 소음에 반응하는 압박 요소 추가 검토
  - **성취감/골 가시화 부족**: 목표치가 우측 상단 작은 텍스트뿐이라 3D 탐사 중 거의 안 보임 — 진행률을 더 크고 디제틱하게(공간 안에서) 노출하는 방향 검토
  - **스토리 부족**: "가벼운 프레이밍만" 원칙은 유지하되, 무거운 컷씬 대신 환경 스토리텔링(캠프의 시각적 변화, 사냥터의 흔적 등) 밀도를 높이는 방향 검토
  - **UI 레이아웃 버그**: `.hint`/`.interact-prompt`가 `white-space:nowrap`인데 `max-width` 제약이 없어, 좁은 창에서 텍스트가 틀 밖으로 삐져나오는 실제 버그 확인(총괄아트 진단) — 총괄기술지원이 다음 착수 시 바로 수정 가능
- **포팅 타이밍 재확인**: 총괄책임자 지시로 Godot 포팅은 웹 프로토타입에서 "재미있게 플레이된다"고 확정된 뒤 한 번에 진행하기로 함 — 그때 GDScript 이식 + 디테일 작업 + 추가 기능까지 함께. 그전까지는 이번 장르 정의를 포함한 모든 설계 결정을 계속 웹 프로토타입 기준으로 진행하고 GDD에 기록만 동기화

## 6차 피드백 — 1인칭 사냥으로 장르 전환 (2026-07-10)
5차 반영(겨울 캐릭터·거래·연쇄)에는 동의하되, 총괄책임자 지시: ① 스팀 게임이니 카드 나열이 아니라 **1인칭으로 직접 움직이며 사냥, 함정에 걸리는 몰입감**을 채택할 것 ② 그래픽을 "일단 샘플로 테스트" 하는 수준이 아니라 **제대로 된 환경을 지금 구축**할 것.

**총괄디렉터 판단(사전 고지)**: 이건 기능 추가가 아니라 장르 전환(2D 카드/타일 UI → 1인칭 3D 탐사)이며, 검증 공백이 이전보다 커진다는 점을 미리 밝힘 — 이 샌드박스엔 디스플레이/GPU가 없어 Godot 2D도 원래 제 눈으로 본 적이 없었는데(항상 헤드리스 로직 검증 + 총괄책임자 로컬 확인), 1인칭 3D는 "카메라감/이동감/함정에 걸리는 서프라이즈" 같은 체감이 핵심이라 이 의존도가 더 커짐. 헤드리스로는 "충돌 트리거가 정확히 동작하는가"까지만 검증 가능 — 이번에도 실제 로컬 플레이가 최종 판단 기준.

**설계 및 구현**:
- **RunManager는 그대로**: 확률/유물/경제 로직 100% 재사용. `bag` 배열의 각 토큰에 안정적 `uid`를 부여하고, `draw(target_uid)`로 임의 위치의 토큰을 순서와 무관하게 뽑을 수 있도록만 확장(기존 `draw()`(인자 없음=마지막 뽑기)는 봇 테스트용으로 그대로 유지 — 하위 호환)
- **`PlayerController.gd`**: CharacterBody3D 1인칭 컨트롤러 — WASD 이동 + 마우스 시점, 중력/바닥 처리. 입력 맵 파일 수정 없이 원시 키코드로 처리(설정파일 최소 수정 전략 유지)
- **`HuntField.gd`**: 사냥 시도가 시작되면 `bag`의 각 토큰을 사냥터에 흩어진 표식(Area3D 트리거)으로 배치 — 전부 **똑같은 눈더미처럼 위장**되어 사냥감/함정 구분 불가(뽑기의 "블라인드" 속성을 공간으로 그대로 이식). 플레이어가 근접하면 그 표식에 걸린 토큰만 `draw(uid)`로 판정 — "카드를 나열하기보다 직접 움직이며 걸린다"는 지시를 그대로 구현
- **정찰(F키) 재해석**: 클릭 UI가 사라졌으므로 "다음 것 미리보기"가 아니라 **임의의 한 표식이 함정인지 미리 감지**(빛 표시)하는 방식으로 변경 — 접근할지 피해갈지 직접 판단하는 공간적 의미로 재배치
- **저장하고 멈추기(Q키)**: 마우스가 시점 조작에 캡처된 상태이므로 클릭 버튼 대신 키 입력으로 전환. 상점/라운드클리어/게임오버 등 "캠프" 국면에서는 기존처럼 마우스 해제 + 버튼 UI 유지(다이제틱하게 만들 필요 없는 메뉴성 결정이라 판단)
- **환경(②)**: 이미지 에셋 0개, 전부 코드 생성 프리미티브 — 설원(PlaneMesh+충돌), 침엽수 실루엣(Cylinder, 무드보드의 "날카로움=위험" 형태 언어), 달빛 방향광 + 안개(Environment), 전부 무드보드 색상표 기반. "샘플을 테스트해보고 나중에 교체"가 아니라 이 자체가 목표 룩의 1차 완성본
- **헤드리스 검증의 한계와 대응**: Area3D 물리 충돌은 헤드리스 스크립트에서 타이밍을 안정적으로 재현하기 어려워, `test_main_scene.gd`를 HuntField의 트리거 핸들러를 직접 호출하는 방식으로 재작성(실제 플레이 시 물리 콜백이 호출하는 것과 동일한 함수) — 마커 개수/베그 사이즈 일치, 거래 수락 후 사냥터 재생성, 정찰 하이라이트, 겨울 표정 전환까지 4회 반복 검증 에러 0건
- 기존 `test_run.gd`/`test_mass_sim.gd`/`test_all_charms.gd`는 RunManager를 직접 구동하므로(Main.gd 경유 안 함) 이번 전환에 영향받지 않음 — 그대로 재검증 통과(전 회귀 무결)
- **HTML 테스트 빌드**: 평면 HTML로는 실제 1인칭 이동/시점을 재현할 수 없어(3D 렌더링 필요), 이번 전환분은 병행 HTML 포팅을 보류함 — Godot 3D 빌드가 유일한 실제 검증 대상이 되었고, 이는 로컬 테스트 의존도가 커졌다는 위 지적과 같은 맥락. 필요시 별도로 가벼운 3D 웹 프로토타입(자체 내장 WebGL, 외부 CDN 의존 없이) 구축을 제안할 수 있음

## 5차 피드백 — 조준/패링 제거, 캐릭터 상호작용·도파민 강화 (2026-07-10)
총괄책임자 피드백: ① 조준-패링은 함정을 회피해 게임이 쉬워지므로 불필요 ② 카드로 토큰 뽑는 구조 자체는 타 보드게임과 같으니, 게임성은 그래픽+캐릭터 등장+그 캐릭터와의 상호작용으로 몰입감을 만들어야 함 ③ 도파민이 안 터짐 ④ 그래픽은 간단·최적화로 유저 부담을 낮출 것. 대응:

- **조준 사냥(Aim & Strike) 전면 제거**: 함정 무효화가 '함정 감지' 유물 축과 겹치는 파워 중복이기도 했음 (총괄기획 동의). 타일 클릭 = 즉시 공개로 단순화
- **겨울을 보이는 캐릭터로 승격**: 대사만 있던 겨울에게 화면 상단 초상(달 + 늑대 실루엣 + 기분 따라 색이 변하는 눈: 평온=아이스블루 / 흡족=앰버(플레이어가 당했을 때) / 경계=적색(플레이어가 잘나갈 때)) 추가. Godot은 `WinterPortrait.gd`의 `_draw()` 프리미티브만으로, HTML은 순수 CSS로 — 이미지 에셋 0개, 렌더 비용 사실상 0 (④ 충족)
- **겨울의 거래**: 사냥 사이에 35% 확률로(2라운드부터) 겨울이 직접 거래를 제안 — "굶주림의 대가"(식량 바치고 다음 사냥 가치 +2) / "겨울의 시험"(함정 +1 대신 수확 +50%) / "차가운 자비"(시도 +1 대신 목표 +4). 수락/거절 모두 겨울이 반응. 뽑기 밖에서 적과 직접 협상하는 진짜 상호작용 층 (② 충족)
- **연쇄(Chain) 시스템**: 한 사냥에서 4연속째 사냥감부터 뽑을 때마다 +1→+2→+3(상한) 보너스. 연쇄가 달아오를수록 화면 연출·사운드 피치가 고조되고(HTML), 함정 한 방에 전부 잃을 판돈도 커짐 — 도파민과 푸시 유어 럭 긴장을 같은 축에 얹음 (③ 충족). 부수 연출: 획득 숫자 플로팅, 팟 카운터 펀치 애니메이션, 연쇄 x N 표시
- **밸런스 재조정**: 연쇄 보너스로 클리어율이 32%→49%까지 올라, 연쇄 시작점 3→4연속·상한 +4→+3으로 낮추고 `BASE_QUOTA` 10→12로 보정. 15만~20만 회 재시뮬레이션 결과 신규 유저 라운드2+ 도달률 40.6%, 게임오버율 56% — 기존(32%)보다 약간 관대하지만 연쇄가 "밀어붙일 이유"를 주는 시스템임을 감안해 채택. Day 2 사람 플레이테스트에서 재검토
- **테스트가 잡아낸 실 버그 수정**: 함정을 뽑으면 `draw()` 내부에서 상태 변경 신호가 동기적으로 화면 재구성을 일으켜, 방금 클릭한 타일이 해제(free)된 뒤 스타일링을 시도해 크래시 + 함정 공개 연출 생략. 가드 플래그를 `draw()` 호출 전에 세우도록 수정, 5회 반복 검증 에러 0건
- **HTML/Godot 동기화 버그 수정**: HTML 빌드의 기본 함정 개수가 2로 남아 있었음(Godot은 1) — 지난 난이도 롤백 때 HTML을 놓친 것. 1로 동기화

## 2차 피드백 및 대응 (2026-07-09, v2 이후)
버전2 플레이 후 추가 피드백: "함정 제거 유물 하나만 뽑으면 이후 전 라운드가 무위험이 됨(사기)", "여전히 카드 뽑아 점수 올리는 것뿐이라 재미없음", "벅샷룰렛/클로버핏/스크레치스크레치/집주인이 너무해(Luck be a Landlord) 등 더 참고할 것".

- **실제 버그 확인 및 수정**: `bust_count`(함정 개수)에 하한선이 없어서, 함정 감소 유물 하나만 뽑아도 0으로 떨어져 그 이후 전 라운드가 완전 무위험이 되는 진짜 문제였음. `MIN_BUST_COUNT=1`로 하한을 걸어 구조적으로 재발 불가능하게 수정 (모든 함정 개수 변경이 `_apply_effect()` 한 곳을 거치므로, 이 한 곳만 고치면 됨)
  - 부작용 처리: 하한선 때문에 "행운의 발자국" 유물이 이미 최소치일 땐 아무 효과 없는 경우가 생겨서, 정찰 1회를 보너스로 얹어 항상 의미 있게 만듦
  - 주의: 처음엔 기본 함정 개수 자체를 1→2로 올려서 하한선 문제를 우회하려 했으나, 대량 시뮬레이션 결과 신규 유저 클리어율이 32%→13%로 폭락해 즉시 되돌림 — 버그 수정과 기본 난이도 상향은 별개 문제였음
- **벅샷룰렛 조사**: 핵심은 "아이템으로 확률/정보를 능동적으로 조작 — 순수 확률 게임에서 자원 관리 게임으로 전환"됨. 우리는 "뽑는다/멈춘다" 둘뿐이라 이 능동적 개입 층이 없었음 → **정찰(Scout)** 메커닉 추가: 사냥마다 1회(유물로 추가 가능) 다음 토큰을 뽑기 전에 미리 확인 가능. 매 순간이 "찍기"가 아니라 "판단"이 되도록 함
- 클로버핏(아이템/부채 압박 구조)과 Luck be a Landlord(심볼 시너지)는 이미 이전 반영분에 녹아 있음. 스크래치형 인크리멘탈은 우리 코어(뽑기+판단)와 결이 달라 이번엔 직접 반영 대상에서 제외 — 필요시 추후 재검토

## 코어 루프
1. 주머니(bag)에서 사냥감 토큰을 한 번에 하나씩 뽑는다 (일반 사냥감 / 함정)
2. 뽑을 때마다 "이번 사냥" 획득량이 누적됨
3. 플레이어는 매 뽑기 후 **계속 뽑을지 / 지금까지 모은 걸 챙기고 멈출지** 선택 — 이 판단이 게임의 핵심 긴장감
4. 함정을 뽑으면 이번 사냥에서 모은 걸 잃음 (유물로 일부 보존 가능)
5. 라운드마다 정해진 사냥 시도 횟수 안에 누적 목표 식량량을 채워야 통과
6. 라운드를 넘길수록 목표 식량량 상승 (겨울이 깊어짐 컨셉)
7. **라운드 클리어 시 "귀환" 여부를 선택** (총괄책임자 지시로 추가된 탈출/익스트랙션 구조)
   - **귀환**: 런을 지금 여기서 안전하게 종료. 지금까지 성과(라운드 수 × 5 + 보유 식량)가 영구 재화 "명성"으로 전환되어 다음 런에도 유지됨. 명성이 일정량 쌓이면 다음 런부터 영구 보너스 해금(예: 시작 시도 횟수 +1, 함정 -1개)
   - **계속 사냥**: 유물 상점으로 진행해 무리를 강화하고 다음 라운드로. 이후 라운드에서 게임 오버(목표 미달)로 죽으면 이번 런에서 쌓은 건 전부 사라짐 — 명성도 얻지 못함
   - 이 선택은 라운드를 클리어할 때마다 매번 다시 주어짐
8. 목표 미달 + 시도 소진 시 게임 오버 → 이번 런 전부 상실. 생존 라운드 수는 로컬 최고 기록으로만 남음 (귀환 시에도 최고 기록 갱신)

## 유물(Charm) 시스템 — 콘텐츠 파이프라인

총괄책임자 지시: 유물이 전부 이득이면 상점이 무의미해짐 → 트레이드오프형·페널티형 유물을 섞어서, 상점에 뜨는 3개가 운 나쁘면 전부 안 좋은 것만 나올 수도 있게 설계 (순수 랜덤 추첨, 등급별 확률 가중치 없음). 이후 "유물 종류를 100개 이상으로 늘리자"는 방향 제시를 받음.

**솔직한 판단**: 100개를 하루 만에 손으로 설계·검증하는 건 비현실적이라고 판단해 총괄책임자께 그대로 전달함 (Balatro 150개/Slay the Spire 75개도 각각 수년의 플레이테스트로 쌓인 콘텐츠). 대신:
1. 유물을 `{stat, amount}` 효과 리스트로 정의하는 **데이터 기반 구조**로 리팩터링 — 새 유물 추가 시 코드 분기(match문) 없이 데이터 항목만 추가하면 됨
2. 기존 6개 수치(함정 개수/먹잇감 가치/안전망/시도 횟수/목표 증가율/캐시아웃 보너스) 외에 **새 메커닉 4종 추가**: 목숨 보험(게임오버 1회 무효), 함정 사전감지(라운드당 자동 회피), 주머니 크기, 귀환 보너스 — 다양성의 축 자체를 넓힘
3. **현재 35종**으로 확장 (좋음 19 / 위험(트레이드오프) 11 / 나쁨(순수 페널티) 5), 100종을 향한 콘텐츠 파이프라인은 앞으로 계속 진행 — 이 구조 위에서는 유물 추가가 데이터 입력 작업이라 확장 자체는 빠름
4. 실플레이 피드백 이후 **사냥감 종류별 시너지 유물 6종** 추가 (아래 "사냥감 심볼" 절 참고) — `type_bonus` 효과 하나만 새로 추가해서 지원, 기존 구조 그대로 재사용

## 대량 봇 시뮬레이션 (100만 회, 2026-07-09)

총괄책임자 지시로 실제 Godot 엔진 프로세스를 1회만 띄운 채 그 안에서 시뮬레이션 루프를 100만 번 도는 방식으로 대량 검증 진행 (`game/test_mass_sim.gd`). 엔진을 100만 번 재시작하는 방식은 비현실적이라 판단해 이 방식으로 대체.

**안정성 결과 (200만 회 누적: 프레시 100만 + 메타누적 100만)**
- 스크립트 에러 0건, 무한루프/스턱 상태 0건, 음수 식량 등 이상치 0건
- 유물 27종 제안 빈도가 통계적으로 균등함 확인 (선택 편향 버그 없음)
- "상점 3개가 전부 나쁨"이 뜨는 실측 확률 0.14~0.15% — 이론상 계산값(C(4,3)/C(27,3)≈0.137%)과 거의 정확히 일치, 랜덤 추첨 로직이 의도대로 동작함을 수학적으로 확인

**치명적 밸런스 문제 발견 및 수정**
- 메타 해금이 전혀 없는 **신규 플레이어 기준(프레시 100만 회)**: 라운드 1도 못 넘기고 전멸하는 비율이 **92.6%**로 확인됨. 반면 메타 해금이 누적된 플레이어 기준(지속 100만 회)은 라운드2 이상 도달률 64.2% — 이 격차가 너무 크다는 건, 첫 플레이 경험이 지나치게 가혹해서 신규 유저 이탈로 이어질 위험이 크다는 뜻
- 조치: `BASE_QUOTA` 14→10, `BASE_ATTEMPTS` 3→4 로 조정 후 재검증 → 프레시 기준 라운드2 이상 도달률 **9.5% → 26.3%**로 개선 (100만 회 재검증 완료)
- 단, 시뮬레이션 봇은 상당히 공격적으로 뽑는 전략(pot<20까지 85% 확률로 계속 뽑기)이라 실제 사람은 이보다 신중하게 플레이해 체감 성공률이 더 높을 가능성이 있음 — 사람 기준 실플레이 검증은 여전히 Day 2 과제로 남음
- `test_mass_sim.gd`는 앞으로 밸런스 변경마다 100만 회 단위로 즉시 재검증할 수 있는 상시 도구로 저장소에 유지
