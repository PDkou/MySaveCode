# Hungry Pack (가제) — 게임 기획서

## 배경 및 방향 전환 기록
- 최초안 "Lane Rush"(레인 회피 아케이드)에서 시장 조사 후 방향 전환
- 총괄마케팅 조사: 2026년 시장에서 CloverPit(슬롯머신 로그라이트, 100만 장+ 판매), Scritchy Scratchy(스크래치카드형 인크리멘탈) 등 "확률 기반 보상 + 라운드마다 상승하는 목표치 + 메타 강화" 루프를 가진 게임들이 강하게 검증되고 있음을 확인
- 단, 위 게임을 그대로 베끼지 않고 **핵심 루프만 참고해 우리만의 오리지널 컨셉으로 재설계**
- 회사명(Howling·늑대)에 맞춰 카지노/슬롯머신 테마 대신 "무리를 이끌고 겨울을 나는 사냥 서바이벌"로 재구성
  - 부가 이유: 슬롯머신을 문자 그대로 구현하면 스팀 심사에서 도박 시뮬레이션 관련 연령등급/규제 이슈가 붙을 수 있음 — 테마 변경으로 회피

## 개요
- **장르**: 푸시 유어 럭(Push-your-luck) 서바이벌 로그라이트 라이트
- **엔진**: Godot 4.7
- **목표 플랫폼**: PC(스팀), 추후 모바일 이식 고려
- **개발 기간**: 1주 — 오프라인 코어 루프 완성 우선, 온라인/스팀 출시는 다음 단계

## 코어 루프
1. 주머니(bag)에서 사냥감 토큰을 한 번에 하나씩 뽑는다 (일반 사냥감 / 함정)
2. 뽑을 때마다 "이번 사냥" 획득량이 누적됨
3. 플레이어는 매 뽑기 후 **계속 뽑을지 / 지금까지 모은 걸 챙기고 멈출지** 선택 — 이 판단이 게임의 핵심 긴장감
4. 함정을 뽑으면 이번 사냥에서 모은 걸 잃음 (유물로 일부 보존 가능)
5. 라운드마다 정해진 사냥 시도 횟수 안에 누적 목표 식량량을 채워야 통과
6. 라운드를 넘길수록 목표 식량량 상승 (겨울이 깊어짐 컨셉)
7. 라운드 클리어 시 유물(참) 3개 중 1개 선택해 무리를 영구 강화 (해당 런 동안 유지)
8. 목표 미달 + 시도 소진 시 게임 오버 → 생존 라운드 수가 최종 점수, 로컬 최고 기록 저장

## 유물(Charm) 목록 (v1, 6종)
| 이름 | 효과 |
|---|---|
| 행운의 발자국 | 함정 토큰 1개 감소 |
| 두꺼운 털가죽 | 먹잇감 가치 +1 |
| 안전망 | 함정에 걸려도 이번 사냥 식량의 50% 보존 |

| 차분한 울음 | 다음 라운드부터 목표 증가폭 20% 감소 |
| 달빛 축복 | 사냥 성공 시 획득 식량 10% 보너스 |

- 프로젝트 로드/씬 빌드/시그널 연결/상태 전이(IDLE→DRAWING→SHOP/GAME_OVER)/함정/캐시아웃/유물 선택까지 스크립트 에러 없이 정상 동작 확인
- 첫 검증에서 초기 밸런스(목표 20, 함정 2/10)가 지나치게 가혹해 5회 연속 라운드1 통과 실패 → 목표 14, 함정 1/10로 조정 후 재검증, 상점 단계까지 정상 도달 확인
- `game/test_run.gd`는 앞으로도 밸런스 조정 시 재사용할 헤드리스 회귀 테스트 도구로 유지

## 브랜딩 반영 (2026-07-09)

## 헤드리스 검증 중 발견한 이슈 (수정 완료)
- `class_name` 전역 클래스 캐시는 에디터를 한 번도 안 연 상태에서는 인식 안 됨(플레이어 실행만으로는 캐시가 안 만들어짐) → `Palette.gd`는 `class_name` 대신 `preload()`로 참조하도록 변경해 이 의존성 자체를 제거함
- 유물 6개를 전부 획득한 이후에도 "유물을 선택하세요" 문구가 계속 뜨던 문제 수정
- 봇 기준 장기 플레이 시 라운드 71까지도 게임오버 없이 지속되는 케이스 확인 — 유물 획득이 끝난 이후(라운드 6~7 이후) 목표 증가율과 플레이어 성장 속도가 균형을 이루면 사실상 무한 지속 가능성 있음. 이건 "엔드리스 모드"로 봐도 되지만, 하이스코어 경쟁 관점에선 상한이 없다는 게 문제일 수 있어 Day 2에서 재검토 필요

## 알려진 리스크
- 시각적 UI 레이아웃/버튼 위치는 헤드리스 환경에서 확인 불가 — 실제 화면에서 확인 필요
- 확률 밸런스는 1차 조정만 거친 상태이며(단순 랜덤 봇 기준), 사람이 실제로 플레이했을 때의 체감 난이도는 별도 확인 필요
- 로고 실제 이미지 파일(logo.png)은 아직 저장소에 없음 — 총괄책임자가 파일로 추가해줘야 인트로에 실제 로고가 표시됨
