## 1. [긴급] `badges/*.png` 재크롭 — 6개 중 5개가 인접 뱃지와 섞여 잘려 있음

앱에서 실사용 중인 등급 뱃지 이미지가 시트에서 잘못 잘려나온 상태. 직접 파일을 열어서
확인함.

| 파일 | 상태 |
|---|---|
| `assets/badges/badge_normal.png` | ✅ 정상 |
| `assets/badges/badge_rare.png` | ❌ 인접 뱃지 조각 섞임 |
| `assets/badges/badge_epic.png` | ❌ 인접 뱃지 조각 섞임 |
| `assets/badges/badge_legendary.png` | ❌ 인접 뱃지 조각 섞임 |
| `assets/badges/badge_hidden_01.png` | ❌ 인접 뱃지 조각 섞임 |
| `assets/badges/badge_hidden_02.png` | ❌ 좌측에 다른 뱃지 조각(검은 원) 섞임 |

**요청**: 원본 시트(`boards/`)에서 각 뱃지 경계를 다시 잡아 5개 파일 재출력. `badge_normal.png`은
정상이니 그대로 참고 크롭 기준으로 써도 됨.

**영향**: 카드 등급 표시(`rarityBadge()`)에 실사용 중이라 사용자가 바로 보게 되는 부분.

## 2. [필요] 런처 아이콘용 — 캐릭터 단독 컷아웃(투명 배경) + 세이프존 여백

현재 앱 아이콘은 `assets/app-icon/app_icon_phone.png`을 그대로 리사이즈해서 쓰는 **레거시
(비적응형) 아이콘**뿐임. Android 8+ 적응형 아이콘(원형/스퀴클 마스크로 자동 크롭되는 방식)을
정식으로 만들려면:

- 캐릭터만 분리된 투명 배경 PNG
- 마스크에 안 잘리도록 안전 영역 확보: 108dp 캔버스 기준 중앙 66dp 안에 캐릭터 핵심 부분이
  다 들어오게 여백 포함
- (선택) 배경 레이어는 단색으로 따로 분리해도 되고, 기존 로고 배경색 그대로 써도 됨

현재 소스는 캐릭터가 프레임 가장자리에 거의 닿아 있어서 그대로 쓰면 귀/발이 잘릴 위험 있어
보류 중.

## 3. [확인 필요] `share_template_square/vertical.png` 사용 방식 스펙

`art/PROJECT_HANDOFF.md`에는 "소셜 공유 카드 만들 때 `share_template_*` 사용"이라고 돼
있는데, 실제 파일을 열어보면 이미 프레임 + MONI 캐릭터(우측 하단, 고정 포즈)가 다 그려져
있는 **완성된 카드 디자인**임. 지금 앱은 사건별로 다른 캐릭터 포즈/등급 프레임을 동적으로
그려야 해서, 이 파일을 그대로 쓰면 캐릭터가 사건 내용과 안 맞거나 우리가 그리는 프레임과
겹쳐버림 (v0.12에서 실제로 이 문제로 리포트 받음 → 지금은 이 파일을 안 쓰고 무늬 배경
`bg_pattern_beige.png` + 자체 프레임 조합으로 대체해둔 상태).

**요청/확인**: 이 템플릿을 원래 의도대로 쓰려면 (a) 캐릭터 자리를 비워둔 배경 전용 버전이
필요한지, 아니면 (b) 이 템플릿 자체를 "이미 완성된 무작위 공유 이미지"로만 쓰고 사건별
동적 렌더링은 지금처럼 별도 조합으로 가는 게 맞는지 방향 확인 필요.

## 4. [신규 — v0.17] `backgrounds/bg_pattern_beige.png`가 실제로는 이음매 없는(seamless)
타일이 아님

파일 이름과 `art/CURRENT_ASSET_POLICY.md`의 설명("동적 공유카드의 기본 패턴 배경")은
반복 타일로 쓰라는 뜻인데, 직접 이 파일만 반복 타일링해서 렌더링해보면 타일 경계마다
뚜렷한 흰색/밝은 이음매 선이 보임 — 파일 자체의 좌우/상하 가장자리 픽셀이 서로
안 맞물리는 상태. 실기기로 내보낸 공유카드에서도 배경이 격자로 나뉘어 보이는 문제로
그대로 나타남.

**요청**: 아래 둘 중 하나로 재작업 필요.
- (a) 좌우/상하 가장자리가 완전히 맞물리는 진짜 seamless 타일로 재출력, 또는
- (b) 반복 없이 한 장으로 쓸 수 있는 최소 1080x1080(정사각 공유용) / 1080x1920(스토리
  공유용) 크기의 전체 배경 이미지 1~2장

어느 쪽이든 색감은 카드 자체의 밝은 크림/골드 톤(`cards/frames/*.png`의 안쪽 배경색)과
너무 튀지 않게 맞춰주면 좋음 — 지금 파일은 살짝 더 차갑고 옅은 핑크빛이 도는 베이지라
카드 안쪽(따뜻한 크림/골드)과 톤이 어긋나 보인다는 실사용자 피드백 있었음.

**임시 조치**: 재작업 전까지 `ShareCardRenderer`는 타일링 대신 이 파일의 바탕색만 뽑은
단색(`rgb(250,245,232)`)으로 채우고 있음 — 이음매는 없지만 장식 패턴 자체는 안 보임.
