# CARD_LAYOUT_SPEC

공유 카드(트레이딩카드 스타일) 좌표의 **단일 진실 공급원(single source of
truth)**. 목업 파이썬 코드, Card Layout Bench 툴, 실제 `ShareCardRenderer.kt`
전부 이 스펙 하나만 보고 그려야 함 — 프레임 이미지를 새로 뽑거나 등급을
바꿔도 이 숫자는 **절대 다시 재지 않음**.

## 원칙

1. **좌표는 이 문서에만 있다.** 프레임 PNG를 열어서 "여기가 헤더판인가?"
   측정하는 코드는 없어야 함. 프레임은 그냥 배경 그림이고, 그 위에 항상
   같은 자리에 얹는다.
2. **5등급이 전부 같은 숫자를 쓴다.** 색상·장식·엠블럼 그림만 등급별로
   다르고, 위치·크기는 절대 등급별로 분기하지 않는다 (메달 표시 크기
   보정 `medal_fix`만 예외 — 이유는 아래 참고).
3. **기준 캔버스는 1024×1536.** 다른 크기(예: 실제 앱의 1080×1080,
   1080×1920)로 낼 때는 전체를 하나의 배율로 통일 스케일링만 하고,
   요소별로 따로 계산하지 않는다.
4. **프레임 배경은 `object-fit: cover`(또는 stretch)로 캔버스에 맞춘다.**
   프레임 자체의 원본 비율이 1024×1536과 정확히 안 맞아도 늘려서 채운다
   — 안쪽 내용물 위치에 전혀 영향 없음.

## 레이어 순서 (아래 → 위)

| # | 레이어 | 비고 |
|---|---|---|
| 1 | 프레임 배경 | 등급별 이미지, 배경 역할만 |
| 2 | 아트 일러스트 | 아트창 박스에 cover로 삽입 |
| 3 | 헤더 패널(반투명) + 등급명 + 제목 | |
| 4 | 정보 패널(반투명) + 통계 + 대사 + 다이아몬드 | |
| 5 | 케이스 번호 태그 | 정보 패널 안쪽, 좌하단 |
| 6 | 로고 | 정보 패널과 같은 줄, 우하단 |
| 7 | 상단 엠블럼(메달 + 아이콘) | 프레임 배경 위, 항상 맨 위 |

## 예외: `medal_fix` (등급별 메달 표시 배율)

엠블럼 위치·크기는 통일이지만, 메달 셸 PNG 자체가 등급마다 "링이 캔버스를
채우는 비율"이 달라서(EPIC/LEGENDARY의 반짝임 장식이 캔버스 가장자리에
더 가깝게 그려짐) 같은 162px로 그리면 링이 작아 보임. 이건 좌표 문제가
아니라 **소스 이미지 자체의 여백 차이**라서, 배율 하나로 보정:

| 등급 | medal_fix |
|---|---|
| NORMAL | 1.00 |
| RARE | 1.00 |
| EPIC | 1.12 |
| LEGENDARY | 1.22 |
| HIDDEN | 1.00 |

메달 이미지를 `162 * medal_fix` px로 그리고, 항상 엠블럼 중심(508,125)에
가운데 정렬. 새 메달 에셋을 받으면 이 배율도 다시 확인.

## 구현 위치

- 파이썬 목업: `sim_tcg_v13.py`의 `GEOMETRY` dict (위 표와 1:1 대응)
- 브라우저 도구: Card Layout Bench의 `DEFAULTS` (같은 좌표계, 드래그로
  덮어쓰면 이 문서도 같이 갱신할 것)
- 실제 앱: `ShareCardRenderer.kt`에 이 표를 `object CardLayout { ... }`
  형태의 상수로 옮기고, `Format.SQUARE`/`STORY`마다 전체를 하나의
  `scale = targetSize / 1536f` 같은 단일 배율로 스케일링 — 요소별 좌표를
  포맷마다 따로 계산하지 않음.

이 문서의 좌표가 바뀌면 (Layout Bench에서 드래그로 조정한 뒤) **이 파일도
같이 업데이트**하고, 그 다음에 목업/실제 코드에 반영하는 순서로 진행.
