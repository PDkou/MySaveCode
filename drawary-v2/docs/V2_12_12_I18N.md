## How it works
- Korean is the source language. Every UI string in the code is `t('한국어')`; `src/i18n/messages/*.ts` holds the Japanese and English text for each Korean text (829 texts). Korean returns the text as is.
- `t('보관품 {n}개', { n })` values; `{n:item|items}` English plural; `tl()` line breaks; `tx()` lets `{name}` be bold/other elements; `K('…')` marks a string kept in a constant (translated with `t()` where shown); a `@tag` suffix (`포함@op`) tells two meanings of one Korean word apart and is never shown.
- Setting `language` (#54 "적용") is saved on the device, applied at once everywhere (the setting lives in the store, so the whole tree re-renders) and survives restarts. First start: the phone's language (ko / ja / otherwise English).
- Messages that cannot be a fixed text: dates and numbers use the language's locale; weekday names are translated; error messages, CSV/print text and the native notification text (re-sent when the language changes) follow the language too.
- `src/i18n/messages.test.ts` fails if a Korean text in the code has no JA/EN text, if a translation is unused, if a `{value}` is lost, if Korean slips into JA/EN, or if Korean text is written in the code outside `t()`/`K()` (sample fixtures and developer-only text are listed in the test).
- Terms (for later texts): 서랍 = ひきだし / drawer, 서랍 칸 = 項目 / field, 보관품 = アイテム / item, 기록 = 記録 / record, 서랍 채우기 = ひきだしに入れる / Fill drawer. Japanese tone: です/ます. (Store copy supplied 2026-10-20 uses ひきだし帳 and "drawers".)

## Fonts
- Korean and English: the approved bundled Noto Sans KR stack (`.drawary-app-shell *` rule, unchanged), so Latin letters are the same font on every screen.
- Japanese: Noto Sans JP (SIL OFL, `public/fonts/noto-sans-jp`, 120 slices + latin, 5.7 MB; the browser downloads only the slices on screen) with Noto Sans KR as the fallback for Korean user data. Applied with `html[lang="ja"]` (a higher-priority rule than the existing `!important` unification). Checked per route: every text element on all 50 checked routes uses one font family in each language.

## Layout
- Tags that were drawn for short Korean words: #10's suggestion tags ("이런 항목은 어때요?") now grow to fit their text in JA/EN (Korean keeps the approved 4-column grid). An overflow scan of all 51 routes in ko/en/ja found no other text outside its box except intentional ellipsis (file names, long drawer names).
- Korean screens were compared before/after the text extraction on all 54 routes: identical except anti-aliasing of a few glyphs/icon edges (the lipstick icon edge differs between runs on its own, too).
